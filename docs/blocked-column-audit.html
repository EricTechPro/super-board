The Blocked Column

One purely additive merge conflict stranded five cards on the finfluencer board and held them there after its own cause was gone. Nothing in the pipeline was wrong. What was missing was a way back out.

2026-08-20 board: EricTechPro/projects/15 super-board 2.3.0

Seven gaps, in the order they cost time

Each one is drawn from this run, not from a checklist. The evidence line is what actually happened; the fix is what would have prevented it.

Blocked is a dead end — nothing re-checks a card whose blocker has closed

P0 · stranding

A card moves to Blocked with a comment naming the issue it waits on. That issue later closes. Nothing reads the comment back. The card sits until a human opens the board and notices.

Evidence

#37 and #40 both named #32 as their blocker and parked correctly. #32 was the only thing they needed. references/run.md:460 ends a run when “only Blocked/Skipped/Done cards remain” — so the closing of #32 could never have woken them, even in a later wave.

Fix

A sweep at the top of every wave. For each Blocked card, re-read its ## Blocked by list and run one gh issue view … -q .state per entry. All CLOSED → move to Ready, comment what changed. No judgement, no model call, ~1 API request per blocker. This is the highest-value change on the list.

mergeable=CLEAN is trusted, and it lies

P0 · correctness

GitHub only answers whether the text conflicts. It says nothing about whether the branch still compiles against the base it is about to land on.

Evidence

This happened twice in one session, from the same cause. PR #89 read MERGEABLE / CLEAN and failed tsc against current staging, because #32 had grown PriceRepository and Dependencies after #89 was tested. Had it merged on GitHub’s word, staging would have gone red.

Fix

A freshness gate in Review: merge the base into a scratch worktree, run typecheck and the suite, then judge. Costs one worktree and one test run per card. A failure bounces to Build as an ordinary pass — it never blocks.

An additive conflict parks the whole downstream chain

P1 · throughput

run.md:433 says a merge conflict “that lane can’t resolve safely” goes to Blocked. In practice no lane is allowed to try, so every conflict is unsafe by default.

Evidence

All 13 hunks in PR #84 were two tickets adding different members to the same interface on purpose. The resolution was “keep both sides” in 12 of them, and one block of setup code moved inside a function. The Reviewer called it “a design merge across two tickets” and stopped — correctly, since it does not push to branches it judges. But three cards waited on a mechanical edit.

Fix

Add a rebase pass. On mergeStateStatus=DIRTY, bounce to Ready with a loop:rebase label rather than to Blocked. The Builder lane already routes resolving-merge-conflicts in decision-policy.md:35 — it is equipped and it is allowed to push. Reserve Blocked for a rebase that fails, or a conflict that is genuinely semantic.

“Proved with a fake” leaves no card owning the real thing

P1 · blind spot

A ticket can legitimately close having proved its behaviour against a stub. Nothing then guarantees the real implementation has a ticket number, so a refusing stub reaches the base branch and waits to be discovered by whoever trips on it.

Evidence

#33’s sixth criterion was, deliberately, “proven through app.request() with a fake repository.” It shipped ingest: notBuiltYet('ingest') to staging. No card owned the Supabase writer. Two tickets later, #34’s Tester hit the wall and had to stop. It was filed as #91 by hand, during this session.

Fix

Two layers. In lint, a thirteenth criterion: a ticket whose ACs prove behaviour against a fake must name the card that owns the real one, or lint offers to file it. In the wave preflight, a repo-level grep for notBuiltYet / NotImplemented / TODO(# on the base branch, asserting each hit has an open card.

Second-order fallout is real work, and no lane budgets for it

P1 · estimation

When a shared interface grows on both sides of a merge, the files that git merged cleanly are where most of the work is. A builder that stops at “no conflict markers left” is not finished.

Evidence

13 conflict hunks across 5 files; then 10 further files on #32’s branch and 1 on #34’s needed edits before tsc passed. The invisible work was roughly twice the visible conflict.

Fix

Mostly covered by the freshness gate above — but say it explicitly in the rebase instructions, so a worker treats a green typecheck, not an empty git diff --diff-filter=U, as the finish line.

Blocker reasons are prose, so the graph can’t be queried

P2 · ergonomics

The block comments this run produced were genuinely good — they named the blocker, showed the verification, and listed the steps out. But reconstructing the dependency chain meant reading five long comments across five issues.

Evidence

The chain was #91 → #34 → #39 and #32 → #37, #40. Nothing on the board expressed that. Block comments already emit machine lines — root-cause-hash:, gh-quota-on-exit:, move-mutation-result: — so the convention exists and is simply not used for this.

Fix

Keep the prose exactly as it is; add one line: blocked-by: 32, 91. The wave sweep reads it instead of parsing the issue body, and /super-board status can render the graph.

A stranger cloning the repo gets v2.0.0 and undocumented dependencies

P2 · open source

Two separate problems, both at the front door. The README’s Quickstart sends people to Releases; Releases is three minor versions behind main. And the Requirements list omits the skill pack the lanes route into.

Evidence

main is 2.3.0; the latest GitHub release is v2.0.0, cut 2026-08-07, 8 commits behind. RELEASE-NOTES.md documents six versions that were never tagged. Separately, the skill files carry 57 references across 12 distinct mattpocock-skills:* skills, and “Requirements” lists Claude Code, gh, jq, bash and a Project board — the skill pack appears only in Credits, at the bottom.

Fix

Tag v2.3.0 and add the release cut to the repo’s own checklist. Move npx skills add mattpocock/skills into Requirements as a first-class install step. Pick one canonical install path — install.sh or the release zip — rather than documenting both as equals.

What I would do first

Ordered by what each buys. The first two are the ones that would have prevented this run entirely.

  1. The Blocked sweep. Pure gh calls, no model judgement. Turns a terminal column into a waiting room.
  2. The freshness gate in Review. One worktree, one test run. Stops a green staging from going red on a merge GitHub called clean.
  3. The rebase pass. Moves mechanical conflicts back to the lane that is allowed to push them.
  4. The blocked-by: line and lint criterion 13. Cheap, and they make the two blind spots visible instead of discoverable.
  5. Cut v2.3.0 and fix Requirements. Nothing to do with the loop — everything to do with whether anyone else can run it.

Where the board ended up

All five cards cleared by hand during this session: #32 and #34 merged, #91 filed for the seam nobody owned, #37, #39 and #40 released back into Ready. Three were picked up by the next wave before this was written.
